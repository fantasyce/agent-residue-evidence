# ARE v0.3.0 Launch Design

**Date:** 2026-08-27
**Status:** Approved

## Goal

Promote Agent Residue Evidence with the same durable public launch surfaces
used by Agent Runtime Proof while preserving ARE's evidence-only safety
boundary. The launch must make installation, evaluation, integration, and
verification possible without requiring a social-network account.

## Release identity

The launch is versioned as `v0.3.0`. The release tag must point at the final
`origin/main` commit containing the site, demonstration, Registry pipeline,
campaign kit, and verification gates. Existing `v0.2.0` artifacts remain
immutable.

## Product story

Tests finishing does not prove that task-owned files, processes, or listening
ports are gone. ARE adds a scoped evidence checkpoint:

```text
observe -> Agent reviews evidence -> user authorizes cleanup
        -> Agent cleans with its own tools -> ARE verifies
```

ARE never deletes, terminates, closes, scans the whole host, uploads, or
collects telemetry. Public materials must distinguish
`NO_CANDIDATES_OBSERVED` from a host-wide cleanliness claim.

## Deliverables

1. A dependency-free GitHub Pages site with one clear claim, workflow,
   boundaries, demo, install path, release link, security link, and accessible
   landmarks.
2. A reproducible demonstration that creates only task-owned residue in a
   temporary root, observes it, stops at human authorization, and supports
   verification after cleanup.
3. MCP Registry metadata and a pinned, OIDC-authenticated publication workflow
   coupled to the successful `v0.3.0` release workflow and exact tag commit.
4. Launch article, FAQ, community copy, maintainer outreach, showcase copy,
   and a machine-readable launch manifest.
5. GitHub Pages, repository homepage and topics, Discussions launch post, and
   an in-repository design-partner issue.
6. Prepared but unpublished copy for Show HN, OpenAI Developer Forum, MCP
   community, Reddit, X, LinkedIn, Chinese communities, and showcases.

## Verification contract

New tests are written before implementation and added to `scripts/check.sh`.
They cover the site, demo boundary, Registry metadata, workflow pinning,
campaign manifest, release-version consistency, and public-link integrity.
The final gate includes the full source suite, privacy/no-network/task
isolation checks, native installed acceptance, deterministic package checks,
security scans, CI on macOS/Linux/Windows, exact release assets, Pages, and the
public Registry record.

## Publication and cleanup

Work happens on `codex/are-promotion-launch` in a task-owned temporary
worktree. A pull request must pass required checks before merge. The release
tag must point to the resulting `origin/main` commit. Task-owned test files,
processes, archives, caches, branch, and worktree are removed after public
verification. The final installed Codex plugin is verified separately from
source and release assets.

## Explicit exclusions

No login, account creation, or post is made on Reddit, X, LinkedIn, Hacker
News, OpenAI Developer Forum, or other external communities in this launch.
Their copy remains prepared and their manifest status remains blocked with the
owner-directed reason.
