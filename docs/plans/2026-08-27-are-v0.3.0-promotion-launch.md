# ARE v0.3.0 Promotion Launch Plan

> Execution is delegated to Codex through release completion. Keep every
> intermediate artifact task-owned and preserve ARE's evidence-only boundary.

**Goal:** Publish ARE v0.3.0 with the same durable GitHub, MCP Registry,
demonstration, and campaign surfaces used for the ARP launch.

**Approach:** Add executable launch contracts to the existing source gate,
implement the smallest public surfaces that satisfy them, then promote only
the exact merge commit after native CI succeeds. The demo runs in an isolated
`ARE_HOME` and temporary scope so it cannot read or modify the user's formal
evidence state.

## 1. Failing launch contracts

- Add site checks for accessibility, required product claims, stable links,
  dependency-free assets, and pinned Pages actions.
- Add demo checks for one scoped file candidate, no cleanup action in ARE, no
  host paths in public output, and complete process/directory cleanup.
- Add Registry render/verification checks for the GitHub repository identity,
  release URL, exact MCPB digest, website URL, and pinned OIDC workflow.
- Add launch-manifest checks for required GitHub channels and explicitly
  blocked external account channels.
- Add all new checks to `scripts/check.sh` and confirm they fail before
  implementation.

## 2. Public site and narrative

- Build `site/index.html`, `site/styles.css`, an accessible workflow SVG,
  and a static 404 page with no scripts, trackers, fonts, or external runtime
  dependencies.
- Add `docs/demo.md`, launch article, FAQ, community posts, maintainer
  outreach, showcase copy, and the initial launch manifest.
- Link the README to the site, demo, latest release, and Registry namespace.

## 3. Reproducible residue demo

- Implement `scripts/demo_task_residue.sh` using a task-owned temporary
  directory, isolated evidence store, and locally built ARE binary.
- Observe a harmless file plus process candidate, finish observation, and
  print a sanitized summary that stops at the user-authorization boundary.
- Add a `--cleanup-and-verify` mode used only by tests to remove the exact
  demo resources with ordinary host tools, verify candidates absent, forget
  the isolated report, and prove zero residue.

## 4. Registry and release automation

- Add atomic Registry metadata rendering and strict verification scripts.
- Add a pinned Pages workflow.
- Add a tag-driven release workflow that verifies tag-to-`origin/main`
  identity, imports the three mandatory native packages from the exact commit,
  builds the MCPB/server metadata/SBOM/checksums, verifies all assets, and
  publishes the GitHub Release.
- Add a pinned `workflow_run` Registry workflow that selects only the
  successful v0.3.0 release, authenticates with GitHub OIDC, publishes, and
  polls the public record.

## 5. Version and release metadata

- Advance VERSION, built-in version, plugin manifest, CI asset names,
  installation docs, README, and changelog to 0.3.0.
- Extend release metadata tests to cover the Pages, release, and Registry
  workflows and all v0.3.0 public surfaces.

## 6. Local and CI acceptance

- Run the launch contracts individually, then `scripts/check.sh`, privacy,
  no-network, task-isolation, installed-native, package reproducibility,
  install lifecycle, and zero-residue checks.
- Push a draft PR, observe all Linux/macOS/Windows jobs, repair any defect
  class across sibling targets, and mark ready only after gates pass.

## 7. Public promotion and closure

- Merge the PR, verify `origin/main`, tag that exact commit, and wait for the
  release, Pages, and Registry workflows.
- Configure repository topics/homepage/Discussions, publish a launch
  Discussion, and create a design-partner Issue. Do not post to external
  authenticated communities.
- Update the launch manifest with verified public URLs and times on a small
  follow-up PR, merge it, and keep the release tag immutable.
- Verify public URLs and the installed Codex plugin separately.
- End the task observation, review its candidate report, remove only
  task-owned worktree/scratch/build artifacts, verify, forget the report,
  delete the merged local/remote launch branch, and report disk/Git state.
